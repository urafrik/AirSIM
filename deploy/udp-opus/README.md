# frp UDP + Opus 验证版（iPhone 84）

这是一版需要真机验证的实验音频传输。默认关闭，现有 TCP/TLS 方式继续保留。

## 工作方式

控制与短信：iPhone → 原有 TLS/TCP 17592 → 安卓。

实验音频：iPhone → AES-256-GCM 加密的 UDP / Opus → frp UDP 17594 → Windows 音频网关 → 安卓原有的 7593 PCM 服务。

不需要替换安卓 APK。荣耀的 AirSIM、Shizuku 和 PCM 音频桥仍须正常运行。电脑上的 Opus 网关在两种编码之间转换；安卓到电脑仍是局域网 PCM/TCP。UDP 音频不经过 stunnel，17593 TCP 保留作手动回退。

## 电脑操作

1. 将整个网关文件夹放在固定位置，保留 `_internal` 文件夹和 `opus.dll`。
2. 双击“启动音频网关.cmd”。首次运行自动创建 `gateway.local.json`。
3. 双击“打开配置.cmd”。确认 `android_host` 是荣耀当前地址，当前为 `192.168.1.88`；端口为 7593。
4. 复制 `key_hex` 的值（64 个十六进制字符），稍后填到 iPhone。它是私密密钥，不要发群聊、提交 GitHub 或贴到问题反馈里。
5. 修改配置后关闭网关窗口，再重新启动。启动日志应显示监听 `127.0.0.1:17594`。

网关默认只监听电脑环回地址，供同电脑 frpc 使用。若 frpc 运行在另一台机器，不可直接沿用该地址。

## 新增一条 frp 映射

| 字段 | 值 |
|---|---|
| 类型 | UDP |
| 本地地址 | 127.0.0.1 |
| 本地端口 | 17594 |
| 公网端口 | 17594，或服务商分配的其他端口 |
| 公网节点 | 与该映射对应的域名；若仍是现有节点，可用 vip.gz.frp.one |

不要修改已有的 17592、17593 TCP 映射，不要将 UDP 映射到 stunnel。单有 UDP 转发表单不能证明 frpc 与公网节点之间也通过 UDP 传输；如果内部承载仍为 TCP，公网丢包时仍可能出现等待重传。

## iPhone 操作

1. 使用原来的签名方式覆盖安装第 84 版 IPA，尽量不要卸载旧版，以保留配对和设置。
2. 设置 → “实验音频：UDP / Opus”：填写音频网关域名、公网 UDP 端口、刚才复制的 `key_hex`，点击“保存 UDP 测试配置”。
3. 打开“启用 UDP / Opus 测试”。当前通话结束后，下一通生效。
4. 使用原来的方式拨打。通话页的音频诊断应出现 `UDP/Opus`；电脑应出现 `session_ready`。
5. 测试关闭屏幕、双方交替讲话和至少 3 分钟连续通话，比较是否卡顿、延迟是否累积。长按通话页音频状态可复制诊断。

测试开关开启时，局域网与外网的直连通话都会使用此音频网关。控制连接仍由现有连接模式决定。为了判断差别，先在外网测试，然后关掉测试开关用 TCP 对照。

**回退：**结束当前通话，关闭 UDP 测试开关，再重新拨打。无需改回 stunnel 或删除 UDP 映射。首版不会在通话中悄悄切换 TCP，以便确认实际测到的是哪条链路。

## 首版包含与限制

- Opus 8 kHz、单声道、20ms 帧，编码目标 12 kbit/s；与现有安卓电话 PCM 格式匹配，不是高清语音升级。
- 60ms 初始抖动缓冲，连续缺帧或迟到后重新对齐（目标等待上限 120ms），乱序整理，迟到包丢弃，Opus PLC 丢包补偿；下一包可用时尝试带内 FEC。FEC 能否恢复取决于编码器和具体音频，不保证每个丢包都可恢复。
- 发送/播放队列设有上限；长时间停顿后丢旧音频，而非持续补播。不是完整 WebRTC，尚无动态码率和完整自适应拥塞控制。
- AES-256-GCM，随机会话 ID，HKDF 双向独立密钥，认证包头，64 包防重放窗口。网关还转交原有安卓 HMAC 配对握手，安卓验证成功才开始传音。
- 8 秒无网关有效响应会报告错误；安卓音频会话主动关闭时直接报告，并在电脑 gateway.log 中记录具体异常。首版不支持通话中跨 Wi-Fi/蜂窝网络迁移，也不增加后台推送能力。
- 诊断计数与日志不录制通话音频。丢包补偿计数可能包含启动/结束时的缺帧，需要结合实际听感判断。
- 手机真机通话和公网 UDP 可达性仍需要用户测试；本地模拟通过不能证明公网稳定性。

## 源码运行与依赖

Windows x64：Python 3.11 以上，`pip install -r requirements.txt`，运行 `prepare_windows.py` 下载经过 SHA256 校验的 Opus DLL，然后运行 `python gateway.py --init` 和 `python gateway.py`。

Windows Opus DLL：conda-forge libopus 1.3.1，BSD 授权。iPhone 从 Xiph Opus 1.5.2 源码编译，下载校验 SHA256；Opus 比特流版本兼容。两端都随产物附带 Opus 授权文件。

验证：`python test_udp.py`。覆盖加密鉴权、篡改、防重放、乱序、迟到、真实 Opus 编解码、丢包补偿，以及通过模拟安卓服务的完整加密 UDP 双向传音。第 84 版还覆盖持续迟到后恢复，iOS CI 会运行真实 Swift 抖动缓冲策略测试。

## 从第 83 版升级

先结束通话并关闭旧电脑网关窗口。将原网关目录中的 gateway.local.json 复制到新版目录（不要公开），沿用原密钥和 UDP 映射；双击新版启动脚本。iPhone 覆盖安装第 84 版，不用重新输入密钥。不要同时运行两个网关。新版会生成 gateway.log，供定位安卓音频桥关闭原因。

## Windows 网关 84.1（兼容 iPhone 84）

针对听到对方偶发断音的情况，调整电脑下行队列：允许短时成批到达，队列容量上限为 12 帧，不预先等待填满；本地排队超过 160ms 的音频仍丢弃。丢弃后保留原始帧序号，让 iPhone 能识别缺口并尝试补偿。日志将下行容量丢弃 down_queue_drops、过期丢弃 down_stale_drops、队列峰值 down_queue_peak、安卓读取间隔峰值 read_gap_ms_peak，与上行时钟重置 up_clock_resets 分开记录。

只需关闭旧网关，把 gateway.local.json 复制到 84.1 目录并启动新版；iPhone、安卓和 frp 设置保持不变。此修订改善一个可能造成断音的队列行为，仍需真机对比，不能保证消除所有公网卡顿。
